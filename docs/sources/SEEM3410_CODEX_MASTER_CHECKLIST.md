## Project specification (replaces the old café proposal)

**Title:** Doctor Staffing Policy in a Hospital Outpatient Clinic.

**Decision:** among 2, 3 and 4 doctors, find the lowest illustrative staffing cost that satisfies a 15-minute doctor-wait target. One shared doctor waiting system, three non-preemptive priority classes: 3 highest, 2 next, 1 lowest; FCFS within class. Consultations in progress never interrupted. Patients immediately enter a pooled FCFS pharmacy after consultation; one counter in the main experiment, two in sensitivity. No abandonment, rejection, preemption, routing to other stages, travel delay, or breaks are modelled. These are explicit model choices, not evidence of real clinical practice.

**Finite-run protocol:** starts empty at t=0; exactly 200 patients generated in each run; the first 240 minutes is a peak period, NOT the run length. Arrivals may continue beyond it. End only when all patients leave. No warm-up deletion because the empty-start finite-run experience is the target. Units: minutes, patients, doctor-minutes, and illustrative cost units. Never describe these synthetic runs as actual hospital days or measured clinical outcomes.

**Primary KPI:** for each run r and staffing c, compute Y_r(c) = np.quantile(doctor_waits, 0.90, method='linear'), including all 200 arriving patients. Primary estimand theta(c) = E[Y_r(c)]. Estimate by averaging independent run-level P90 values. A mean run-level P90 <= 15 min satisfies the point-estimate criterion; also report its CI, the fraction of runs whose P90 <= 15, and the actual service level fraction(wait <= 15). A policy is strongly supported if the upper endpoint of its two-sided 95% CI is <= 15; if the CI straddles 15, mark it uncertain and use additional independent runs or report inconclusiveness. Do not conflate this target with pooled P90, a guarantee of 90% compliance every run, or the peak-only P90. Show pooled P90 separately if useful; define it explicitly. A 15-minute target is illustrative, not an official clinical benchmark.

**Primary experiment:** 50 fresh independent replications using a data-calibrated empirical arrival-gap model and empirical service/priority distributions (Week 5); reuse each generated patient table across 2/3/4 doctors (CRN, Week 6). Also run the 50 original baseline traces across all three policies as a paired replay benchmark. Use a continuous piecewise Poisson arrival model as an alternative-input sensitivity experiment, not as a proven data-generating process. This is a provisional implementation choice to satisfy the latest proposal's new-patient generation commitment while retaining exact original-data checks. Present replay and fresh experiments separately. If the team has already explicitly selected replay as primary, retain that choice in config and report the fresh empirical experiment alongside it. Never switch primary model after viewing staffing results.

**Defaults, clearly illustrative:** root seed 3410; fresh confirmation root seed 93410; R=50 per policy/condition; cost per doctor-hour 100 cost units; scheduled horizon 1080 min (18 hours, NOT a real recorded shift). Keep wage and scheduled hours configurable. Cost is proportional to headcount under common scheduled hours. Report last arrival, last doctor completion, final departure and overtime busy-minutes separately. If an arrival occurs after the assumed schedule, flag it explicitly. For optional overtime cost, define a separate busy-time overtime proxy and premium (1.5 times wage, test 1.0/1.5/2.0); it is not actual payroll. No fabricated HKD wage or claim about the hospital's shift. If none meets target, explicitly report no feasible candidate among 2–4 doctors.
